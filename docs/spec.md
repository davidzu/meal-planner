# spec.md — Buildable gap list

Contract for the developer (stage 3) and the tester (stage 4). Implements `docs/ADR-001-architecture.md` against the partial app. Design sources: `docs/02`–`docs/07` and `docs/screens/week-planner.md`.

**Rules**

- Implement items in numeric order. Do not skip.
- Do not change the data model except item **2.1**.
- Do not add gems except items **1.1** and **1.2**.
- Do not edit this file or the ADR.
- Each requirement lists the files to create or modify. “Modify” means the named file already exists.
- Tester owns every item in §14. Developer owns §1–§13.
- Done means: the acceptance line is true, not merely that the file exists.

Existing (do not rebuild): 12 models, 8 controllers, most views, `db/seeds.rb` (10 real recipes), CSS tokens in `application.css`, Stimulus `toast` + `picker-filter`, importmap-vendored Turbo/Stimulus.

## 1. Foundation — gems, railties, locale, DRY household

### 1.1 Add Propshaft

- **Files:** `Gemfile`, `Gemfile.lock` (via `bundle install`)
- **Do:** `gem "propshaft"` in the default group. No extra config file.
- **Why:** there is no asset pipeline; `stylesheet_link_tag "application"` cannot serve `app/assets/stylesheets/application.css`.
- **Accept:** `bin/rails runner 'puts Rails.application.config.assets'` boots; a request to `/` includes a digest (or Propshaft) stylesheet link that 200s.

### 1.2 Add test gems (tester will use them; developer adds them now)

- **Files:** `Gemfile`, `Gemfile.lock`
- **Do:** in `group :test`: `gem "capybara"` and `gem "selenium-webdriver"`.
- **Accept:** `bundle list` shows both. No other new gems.

### 1.3 Enable Test::Unit and system tests

- **Files:** `config/application.rb`
- **Do:**
  - Uncomment `require "rails/test_unit/railtie"`.
  - Delete `config.generators.system_tests = nil`.
- **Accept:** `bin/rails generate test_unit:model Household` would work (do not leave a generated stub). `Rails.application.config.generators.system_tests` is not `nil`.

### 1.4 Spanish locale and Mexico City time zone

- **Files:** `config/application.rb`; **create** `config/locales/es.yml`; keep `config/locales/en.yml` (unused is fine).
- **Do:**
  ```ruby

  config.time_zone = "America/Mexico_City"
  ```
  `es.yml` must define `date.day_names`, `date.abbr_day_names`, `date.month_names`, `date.abbr_month_names`, and `date.formats.short` (e.g. `"%d %b"`) so `Week#label` and `Day#name` render Spanish (`Lunes`, `ago`).
- **Accept:** `I18n.l(Date.new(2026,8,24), format: :short)` is Spanish; `Day#name` for a Monday is `Lunes` (or `lunes` capitalized by the existing `.capitalize`).

### 1.5 DRY `current_household`

- **Files:** `app/controllers/application_controller.rb`; then `weeks_controller.rb`, `shopping_lists_controller.rb`, `users_controller.rb`, `households_controller.rb`, `settings_controller.rb`

## 3. Models

### 3.1 `ListItem` uniqueness matches the new index

- **Files:** `app/models/list_item.rb`
- **Do:** `validates :ingredient_id, uniqueness: {scope: [:shopping_list_id, :unit]}` (replace the current `scope: :shopping_list_id`).
- **Accept:** two list items on one list, same ingredient, different units, both valid; same unit is invalid.

### 3.2 `MenuDay` uniqueness matches the DB index

- **Files:** `app/models/menu_day.rb`
- **Do:** replace `validates :recipe_id, uniqueness: {scope: [:day_id, :meal_type]}` with `validates :meal_type, uniqueness: {scope: :day_id}`. Keep meal_type inclusion and servings numericality.
- **Accept:** a second row with the same `day` + `meal_type` is invalid even if `recipe_id` differs.

### 3.3 Nested attributes on `Recipe`

- **Files:** `app/models/recipe.rb`
- **Do:** `accepts_nested_attributes_for :recipe_ingredients, allow_destroy: true, reject_if: :all_blank`. Keep existing associations/validations.
- **Accept:** `Recipe.create!(name: "X", base_servings: 2, recipe_ingredients_attributes: [{ingredient_id:, quantity: 1, unit: "pieza"}])` persists the join row. The recipe form can save ingredients (today it cannot).

### 3.4 Delete broken `by_difficulty` scope

- **Files:** `app/models/recipe.rb`; `app/controllers/recipes_controller.rb`
- **Do:** remove `scope :by_difficulty`. Remove `.by_difficulty(params[:difficulty])` from `RecipesController#index`. Do **not** add a `difficulty` column.
- **Accept:** `grep -r by_difficulty app` is empty. Index still filters by `q`, `tag_id`, `max_time`.

### 3.5 Ingredient find-or-create from a name

- **Files:** `app/models/ingredient.rb` and/or `app/models/recipe.rb`
- **Do:** a class method `Ingredient.find_or_create_named!(name, unit: nil, category: nil)` that strips name, `find_or_create_by!(name:)` with defaults `base_unit: unit.presence || "pieza"`, `category: category.presence || "abarrotes"`. Recipe nested attributes may still send `ingredient_id`; the form (8.3) will also send a name for new ingredients — handle that in the controller (6.6) using this method.
- **Accept:** calling it twice with `"Cilantro"` returns the same record; does not duplicate.

### 3.6 `Week#clear!`

- **Files:** `app/models/week.rb`
- **Do:** `clear!` destroys all `menu_days` of this week’s days (not the days themselves, not the shopping list).
- **Accept:** a week with 3 slots → `clear!` → `filled_slot_count == 0`; 7 days remain.

### 3.7 Week navigation dates without persisted neighbors

- **Files:** `app/models/week.rb`
- **Do:** `previous_start_date` = `start_date - 7.days`; `next_start_date` = `start_date + 7.days`. Keep `copy_from`, `build_days!`, `normalize_start_date`.
- **Accept:** a brand-new week still knows last Monday and next Monday.

## 6. Controllers

### 6.1 `WeeksController#show` honors `:id`

- **Files:** `app/controllers/weeks_controller.rb`
- **Do:**
  - If `params[:id]` present: `@week = current_household.weeks.find(params[:id])`.
  - Else (root): `@week = Week.for_household_and_date(current_household, params[:date] || Date.current)` then `save!` if new.
  - Always `build_days!`.
  - Set `@previous_start_date` / `@next_start_date` from the model (3.7), **not** only from persisted neighbor rows. Optionally still load `@previous_week` for the copy button (latest persisted week with `start_date < @week.start_date`).
- **Accept:** viewing `/weeks/:id` for next week, assigning a recipe, redirecting to `week_path(@week)` still shows **that** week, not today.

### 6.2 `WeeksController#copy` is POST and safe

- **Files:** `app/controllers/weeks_controller.rb`
- **Do:** `source = current_household.weeks.find(params[:source_week_id])`; `build_days!`; `copy_from(source)`; redirect to `week_path(@week)` with notice. Do not copy across households.
- **Accept:** POST copies empty slots only; filled slots stay. GET `/weeks/:id/copy/...` is 404/no-route.

### 6.3 `WeeksController#clear`

- **Files:** `app/controllers/weeks_controller.rb`
- **Do:** `before_action` includes `:clear`; call `@week.clear!`; redirect with notice `"Semana vaciada."`.
- **Accept:** POST clear → 0 filled slots; 7 day columns remain.

### 6.4 `WeeksController#update` still permits `people_count`

- **Files:** `app/controllers/weeks_controller.rb`; `app/views/weeks/show.html.erb`
- **Do:** keep `week_params` = `:start_date, :people_count`. Add a small toolbar form: number field “Personas” submitting PATCH to `week_path(@week)`. This value is the default servings for new assignments (6.5).
- **Accept:** changing Personas to 6 persists; next assign uses 6 servings.

### 6.5 `MenuDaysController` create / update / destroy

- **Files:** `app/controllers/menu_days_controller.rb`
- **Do:**
  - `create`: `find_or_initialize_by(meal_type:)`; set `recipe_id`; default `servings` to `params.dig(:menu_day, :servings).presence || @week.people_count`; save; redirect `week_path(@week)`.
  - **add `update`:** permit `:servings` (and optionally `:recipe_id` for re-pick); redirect `week_path(@week)`.
  - `destroy`: unchanged, redirect `week_path(@week)`.
  - `new`: keep `layout: false`; load `@recipes = Recipe.includes(:tags).order(:name)`.
- **Accept:** assigning from the picker writes `servings == week.people_count`. Patching servings on a filled slot persists and is used by `regenerate!`.

### 6.6 `RecipesController` — F5 return-to-slot + author + nested ingredients

- **Files:** `app/controllers/recipes_controller.rb`
- **Do:**
  - `index`: drop `by_difficulty`; keep search/tag/time.
  - `create`/`update`: before save, for each nested ingredient with a `name` and no `ingredient_id`, call `Ingredient.find_or_create_named!`.
  - `create`: if any household user exists, set `author` to the first `planificador` else first user (v1 has no session).
  - `create` success: if `params[:return_week_id]`, `return_day_id`, `return_meal_type` present, create/update that `MenuDay` with this recipe and `servings: week.people_count`, then redirect to `week_path(week)` with notice. Else redirect to the recipe.
  - `destroy`: keep `restrict_with_error`; on failure redirect with alert (already).
- **Accept:** creating “Tacos” from the picker footer with return params lands the recipe in the originating slot. Creating from `/recipes/new` without return params goes to show.

### 6.7 `ShoppingListsController`

- **Files:** `app/controllers/shopping_lists_controller.rb`
- **Do:**
  - `index`: `current_household.weeks.joins(:shopping_list).includes(shopping_list: :list_items).order(start_date: :desc)`.
  - `create`: find week in household; `shopping_list || build_shopping_list`; `regenerate!`; redirect to the list.
  - `toggle_item`: unchanged (PATCH flips `purchased`).
- **Accept:** generating from a week with mixed units of one ingredient creates two rows (relies on 2.1). Index does not 500 when some weeks have no list.

### 6.8 `HouseholdsController` / `UsersController` / `SettingsController`

- **Files:** those three
- **Do:** households only `update` (name). Users CRUD as now, always scoped to `current_household`. Settings `#index` assigns `@members = current_household.users.order(:email)` and `@household`.
- **Accept:** `/households/:id/edit` is no-route. PATCH name still works from `/settings`.
